# 功能规格说明：新闻中心页 (News Center Page)

**功能分支**: `005-news-center-page`
**创建日期**: 2026-02-27
**状态**: 草稿
**输入**: 用户描述："News 新闻中心页 - 品牌动态、公关稿件和活动发布阵地"

## 用户场景与测试 _(必填)_

### 用户故事 1 - 浏览新闻中心 (优先级: P1)

作为网站访客，我希望进入新闻中心页时能看到一个视觉冲击力强的首屏 Hero Banner（包含标题 "Aura News Center" 和副标题），以及下方以网格形式展示的新闻文章卡片，以便我能快速了解 Aura 的最新新闻、活动和故事。

**优先级原因**: 新闻列表是本页面的核心用途。没有它，新闻中心将无内容可展示，对访客毫无价值。

**独立测试**: 可通过导航至新闻页面，验证 Hero Banner 正确显示、新闻卡片以网格/瀑布流布局渲染在分类标签下方来完成测试。

**验收场景**:

1. **假设**访客导航至新闻页面，**当**页面加载完成，**则**显示全宽 Hero Banner，包含艺术感背景图、标题 "Aura News Center" 和副标题 "Stay up-to-date with Aura's latest news, events, and stories."
2. **假设**访客在新闻页面，**当**向下滚动越过 Hero Banner，**则**看到新闻文章卡片以大小混合的瀑布流/网格布局展示。
3. **假设**访客正在浏览新闻网格，**当**查看任意新闻卡片，**则**每张卡片展示一张特色图片和文章标题标签（如 "My Aura stories"）。

---

### 用户故事 2 - 按分类筛选新闻 (优先级: P2)

作为网站访客，我希望通过分类标签（Breaking news、Event、About Aura）筛选新闻文章，以便聚焦于我最感兴趣的内容类型。

**优先级原因**: 分类筛选增强了内容的可发现性，让访客无需翻阅所有文章即可找到特定类型的内容。这是页面上的核心交互功能。

**独立测试**: 可通过点击每个分类标签，验证新闻卡片更新为仅展示该分类的文章来完成测试。

**验收场景**:

1. **假设**访客在新闻页面，**当**页面加载完成，**则**在新闻网格上方显示三个分类标签："Breaking news"、"Event" 和 "About Aura"，默认选中 "Breaking news"。
2. **假设**访客正在浏览 "Breaking news" 标签下的新闻，**当**点击 "Event" 标签，**则**新闻网格更新为仅展示 "Event" 分类的文章。
3. **假设**访客在不同分类标签间切换，**当**网格内容过渡时，**则**更新过程流畅且无需整页刷新。
4. **假设**访客选择了一个没有已发布文章的分类，**当**网格更新时，**则**显示一条友好的空状态提示（如 "该分类暂无文章"）。

---

### 用户故事 3 - 查看新闻文章详情 (优先级: P2)

作为网站访客，我希望点击新闻卡片后能在专门的详情页阅读完整文章，以便深入了解 Aura 的新闻内容。

**优先级原因**: 没有详情页，新闻卡片就是死胡同。用户需要能够访问完整的文章内容，新闻中心才有实际价值。

**独立测试**: 可通过点击任意新闻卡片，验证其导航至详情页并展示完整文章内容和正确排版来完成测试。

**验收场景**:

1. **假设**访客正在浏览新闻网格，**当**点击一张新闻卡片，**则**导航至该文章的专属详情页。
2. **假设**访客在新闻详情页，**当**页面加载完成，**则**显示文章的特色大图（Hero 格式）、文章标题、发布日期，以及排版良好的正文内容。
3. **假设**访客正在阅读新闻文章，**当**希望分享该文章，**则**可使用分享功能（至少支持复制链接）。
4. **假设**访客阅读完文章，**当**希望返回新闻列表，**则**有清晰的导航路径（返回新闻中心）可用。

---

### 用户故事 4 - 新闻卡片悬停交互 (优先级: P3)

作为网站访客，我希望鼠标悬停在新闻卡片上时能看到视觉反馈，以便知道卡片是可交互、可点击的。

**优先级原因**: 悬停效果通过提供明确的可点击提示来提升感知质量和可用性，增强整体浏览体验。

**独立测试**: 可通过将鼠标悬停在新闻卡片上，验证视觉反馈（如图片缩放、遮罩效果）平滑出现来完成测试。

**验收场景**:

1. **假设**访客在支持悬停的设备上浏览新闻网格，**当**鼠标悬停在一张新闻卡片上，**则**卡片展示视觉悬停效果（如轻微图片缩放或浅色遮罩）。
2. **假设**访客在不支持悬停的触屏设备上，**当**点击新闻卡片，**则**直接导航至详情页，无需悬停交互。

---

### 边界情况

- 访客进入新闻页面但完全没有已发布的文章时怎么办？应展示品牌插图 + 提示文案 + "查看全部新闻"引导按钮的空状态区域，而不是空白页。
- 新闻文章的特色图片加载失败时怎么办？应展示一个与品牌风格一致的兜底占位图。
- 访客直接访问一个不存在的新闻详情 URL 时怎么办？应展示友好的 404 页面，并提供返回新闻中心的链接。
- 在弱网环境下怎么办？页面应保持可用，内容渐进加载，图片显示占位状态。
- 当新闻文章数量很多（50+ 篇）时怎么办？页面应通过无限滚动优雅地处理大量内容，不出现性能下降。

## 需求 _(必填)_

### 功能需求

- **FR-001**: 新闻中心页必须展示一个全宽 Hero Banner 区域，包含视觉冲击力强的艺术感背景图、标题 "Aura News Center" 和副标题 "Stay up-to-date with Aura's latest news, events, and stories." 页面整体视觉风格必须与网站其他页面保持一致（容器宽度、配色体系、字体、圆角、动画、间距节奏均沿用现有风格体系）。
- **FR-002**: 页面必须在新闻网格上方展示三个分类筛选标签："Breaking news"、"Event" 和 "About Aura"。
- **FR-003**: 页面首次加载时，"Breaking news" 标签必须默认选中。
- **FR-004**: 点击分类标签必须筛选展示的新闻卡片，仅显示该分类的文章，且无需整页刷新。
- **FR-005**: 新闻文章必须以图片为主的卡片形式展示在瀑布流/网格布局中，卡片大小有所变化以营造视觉层次感，与设计稿一致。
- **FR-006**: 每张新闻卡片至少必须展示：一张特色图片和文章标题。标题限制为单行显示，超出部分以省略号（...）截断。
- **FR-007**: 每张新闻卡片必须可点击，并导航访客至专属的新闻文章详情页。
- **FR-008**: 新闻详情页采用杂志风格布局：顶部区域左侧大图占约 60% 宽度，右侧并排展示文章标题（大号粗体）、发布日期和分类标签；下方为全宽正文内容区域（居中窄栏，便于阅读）；底部展示"复制链接"分享按钮和"返回新闻中心"导航链接。移动端顶部区域改为上下堆叠（图片在上，标题/日期在下）。
- **FR-009**: 在支持悬停交互的设备上，新闻卡片必须展示悬停效果（如轻微图片缩放或遮罩）。
- **FR-010**: 新闻中心页必须完全响应式，在桌面端、平板端和移动端屏幕尺寸上提供优化的浏览体验。桌面端采用瀑布流/网格布局（大小混合卡片），移动端切换为单列垂直列表（每张卡片全宽显示，图片 + 标题上下排列）。
- **FR-011**: 当选中的分类没有文章时，系统必须展示空状态区域，包含：一个与品牌风格一致的轻量插图（如 Aura Logo 简化图形）、提示文案（如"暂无相关新闻，请稍后再来查看"）、以及一个"查看全部新闻"引导按钮（点击后切换至默认分类标签）。
- **FR-012**: 新闻详情页必须提供至少一种分享机制（最低要求：复制文章链接）。
- **FR-013**: 当某个分类的文章数量超出单屏显示范围时，系统必须在访客向下滚动时自动加载更多文章（无限滚动），提供无缝浏览体验，无需手动翻页。

### 关键实体

- **新闻文章 (News Article)**: 代表一条新闻。关键属性：标题、特色图片、分类（Breaking news / Event / About Aura）、发布日期、文章正文内容、URL 标识符。
- **新闻分类 (News Category)**: 代表用于筛选的内容分类标签。关键属性：名称、展示顺序。固定集合："Breaking news"、"Event"、"About Aura"。

## 成功标准 _(必填)_

### 可衡量的成果

- **SC-001**: 访客从新闻中心页出发，最多 2 次点击即可找到并阅读任意一篇新闻文章（如需要，1 次点击筛选分类，1 次点击打开文章）。
- **SC-002**: 新闻中心页在标准宽带连接下，3 秒内加载完成并呈现完整视觉效果。
- **SC-003**: 分类标签筛选在用户交互后 1 秒内完成内容更新。
- **SC-004**: 100% 的新闻卡片提供明确的可交互视觉提示（桌面端悬停状态，移动端适当的点击目标尺寸）。
- **SC-005**: 页面布局正确适配至少 3 个断点（移动端、平板端、桌面端），无内容溢出或布局错乱。
- **SC-006**: 访客从任意新闻详情页 1 次点击即可返回新闻中心列表。

## 澄清记录

### 会话 2026-02-27

- Q: 文章标题文案溢出时如何处理？ → A: 限制为单行显示，超出部分以省略号（...）截断。
- Q: 新闻中心页是否遵循现有视觉风格体系？ → A: 严格遵循现有风格体系（max-w-7xl 容器、品牌粉色强调色、Montserrat 字体、rounded-2xl 圆角、Framer Motion ScrollReveal 动画、py-12/py-20 间距），不引入新的视觉元素。
- Q: 移动端不适合瀑布流，应采用什么布局？ → A: 移动端采用单列垂直列表，每张卡片全宽显示（图片 + 标题），上下依次排列。
- Q: 文章详情页采用什么布局风格？ → A: 杂志风格布局——顶部左侧大图（60%）+ 右侧标题/日期/分类并排，下方全宽正文，底部分享按钮和返回导航。移动端顶部改为上下堆叠。
- Q: 空状态页面应展示什么内容？ → A: 品牌插图（Aura Logo 简化图形）+ 提示文案（"暂无相关新闻，请稍后再来查看"）+ "查看全部新闻"引导按钮（切换至默认分类）。
- Q: 新闻数据层采用什么模式？ → A: 使用 React Hook 封装（`useNewsArticles(category?, page?)`, `useNewsArticle(slug)`），内部管理 loading/error/data 三态，当前从 mock 数据返回并模拟分页加载逻辑（每次请求返回固定条数 + hasMore 标识），后期可直接替换为真实 API 请求而无需修改组件调用方。

## 假设

- 新闻文章数据通过 React Hook 封装层获取（`useNewsArticles(category?, page?)`、`useNewsArticle(slug)`），Hook 内部管理 loading/error/data 三态。当前版本从本地 mock 数据返回并模拟异步分页加载逻辑（每次请求返回固定条数 + hasMore 标识），后期可直接替换为真实 API 请求而无需修改组件调用方。
- 三个分类标签（"Breaking news"、"Event"、"About Aura"）在初始版本中为固定集合。添加或修改分类不在本功能范围内。
- Hero Banner 背景图为静态设计素材，非动态管理内容。
- 详情页的社交分享功能初期仅提供 "复制链接" 机制。完整的社交媒体分享按钮（Facebook、Twitter 等）可作为后续增强。
- 由于未提供新闻详情页的专门设计稿，详情页采用杂志风格布局（顶部左图右文并排 + 下方全宽正文），整体视觉风格沿用网站现有体系。
- 瀑布流/网格卡片布局遵循设计稿，采用大小混合的卡片以营造视觉层次。具体的卡片尺寸分布参照提供的设计稿。
- 每个分类标签下的新闻文章按发布时间倒序排列（最新的在前）。
