## 用户场景与测试 _(必填)_

### 用户故事 0 - 管理员登录校验 (优先级: P0)

运营人员访问 `/admin/content` 路由，系统首先展示登录表单（账号+密码），要求输入固定凭据进行身份校验。输入正确的账号 `admin` 和密码 `aura1509` 后方可进入内容管理页面。校验状态保存在 sessionStorage 中，关闭浏览器标签页后需重新登录。

**优先级原因**: 管理页面必须有访问控制，防止未授权用户操作文章内容。这是所有管理功能的前置条件。

**独立测试**: 导航至 `/admin/content`，验证首先显示登录表单而非文章列表。输入错误凭据显示错误提示，输入正确凭据后进入管理页面。

**验收场景**:

1. **假设** 未登录的用户，**当** 访问 `/admin/content`，**则** 显示登录表单，包含账号和密码输入框及登录按钮
2. **假设** 登录表单已显示，**当** 输入错误的账号或密码并点击登录，**则** 显示「账号或密码错误」的错误提示，不进入管理页面
3. **假设** 登录表单已显示，**当** 输入正确凭据（admin / aura1509）并点击登录，**则** 登录表单消失，显示文章管理页面
4. **假设** 已登录状态，**当** 刷新页面，**则** 保持登录状态，直接显示管理页面（sessionStorage）
5. **假设** 已登录状态，**当** 关闭浏览器标签页后重新访问，**则** 需要重新登录

### 用户故事 1 - 浏览文章列表与搜索筛选 (优先级: P1)

运营人员登录后进入内容管理页面，看到所有已有文章以表格形式展示。表格包含标题、标签（分类）、图片路径等关键字段，每行带有操作按钮。运营人员可以通过关键词搜索文章标题，也可以按标签筛选文章列表。列表支持分页，每页展示合理数量的文章。

**优先级原因**: 文章列表是内容管理的基础视图，所有其他操作（编辑、删除、预览）都依赖于此。没有列表页，整个管理功能无法运作。

**独立测试**: 导航至 `/admin/content`，验证文章列表正确渲染所有文章数据，搜索框输入关键词后列表实时过滤，分类下拉选择后列表按分类筛选。

**验收场景**:

1. **假设** 已登录的运营人员访问内容管理页面，**当** 页面加载完成，**则** 以表格形式展示所有文章，包含标题、标签、图片路径列和操作列
2. **假设** 文章列表已加载，**当** 在搜索框中输入关键词，**则** 列表实时过滤仅显示标题包含关键词的文章
3. **假设** 文章列表已加载，**当** 选择某个标签筛选项，**则** 列表仅显示该标签下的文章
4. **假设** 文章总数超过每页限制，**当** 点击分页控件，**则** 正确翻页并展示对应页的文章
5. **假设** 搜索或筛选后无匹配结果，**当** 列表为空，**则** 显示友好的空状态提示

---

### 用户故事 2 - 新增文章 (优先级: P1)

运营人员需要发布一篇新文章。点击页面顶部的「新增文章」按钮后，弹出模态框表单。表单仅包含 4 个字段：图片（支持 webp/png/jpg 格式，保存上传图片路径）、标签（固定三选一：Breaking news / Event / About Aura）、标题和内容。填写完成后点击「保存」，系统自动生成 slug、imageAlt、publishDate 等衍生字段，文章添加到列表中，弹窗关闭。

**优先级原因**: 新增文章是内容管理的核心创建功能。运营人员需要能够快速添加新文章内容。

**独立测试**: 点击「新增文章」按钮，填写表单所有必填字段，点击保存，验证新文章出现在列表中。

**验收场景**:

1. **假设** 运营人员在文章列表页，**当** 点击「新增文章」按钮，**则** 弹出模态框表单，包含图片、标签、标题、内容四个字段，均为空/默认值
2. **假设** 新增表单已打开，**当** 填写所有字段并点击「保存」，**则** 系统自动生成 id、slug、imageAlt、publishDate、summary、cardSize 等衍生字段，新文章添加到列表中，弹窗关闭，显示成功提示
3. **假设** 新增表单已打开，**当** 未填写必填字段直接点击「保存」，**则** 表单显示验证错误信息，不关闭弹窗
4. **假设** 新增表单已打开，**当** 点击「取消」或弹窗外区域，**则** 弹窗关闭，不保存任何数据
5. **假设** 新增表单中图片字段，**当** 上传/选择图片后，**则** 表单保存图片文件路径（支持 webp/png/jpg 格式）

---

### 用户故事 3 - 编辑文章 (优先级: P1)

运营人员需要修改已有文章的内容。在文章列表中找到目标文章，点击该行的「编辑」按钮，弹出与新增相同的模态框表单，但已预填充当前文章数据。修改后点击「保存」，文章信息更新，弹窗关闭。

**优先级原因**: 编辑是 CRUD 的核心操作之一，运营人员经常需要修正或更新已有文章内容。

**独立测试**: 在列表中选择一篇文章点击「编辑」，验证表单预填充了该文章的所有数据，修改某个字段后保存，验证列表中对应文章已更新。

**验收场景**:

1. **假设** 运营人员在文章列表页，**当** 点击某篇文章的「编辑」按钮，**则** 弹出模态框表单，所有字段预填充该文章的当前数据
2. **假设** 编辑表单已打开，**当** 修改任意字段并点击「保存」，**则** 文章数据更新，弹窗关闭，列表中该文章信息同步更新
3. **假设** 编辑表单已打开，**当** 点击「取消」，**则** 弹窗关闭，文章数据不变

---

### 用户故事 4 - 删除文章 (优先级: P2)

运营人员需要删除不再需要的文章。在文章列表中点击「删除」按钮，弹出确认对话框。确认删除后，文章从列表中移除。

**优先级原因**: 删除是内容管理的基本功能，但使用频率低于新增和编辑，需要确认机制防止误操作。

**独立测试**: 点击某篇文章的「删除」按钮，确认删除对话框出现，点击确认后验证文章从列表中消失。

**验收场景**:

1. **假设** 运营人员在文章列表页，**当** 点击某篇文章的「删除」按钮，**则** 弹出确认对话框，显示即将删除的文章标题
2. **假设** 确认对话框已打开，**当** 点击「确认删除」，**则** 文章从列表中移除，显示删除成功提示
3. **假设** 确认对话框已打开，**当** 点击「取消」，**则** 对话框关闭，文章保持不变

---

### 用户故事 5 - 预览文章详情 (优先级: P2)

运营人员在编辑或新增文章后，需要查看文章在前台的实际展示效果。在文章列表中点击「预览」按钮，系统在新浏览器窗口/标签页中打开该文章的前台详情页（`/news/[slug]`），运营人员可以直接看到文章的最终渲染效果。

**优先级原因**: 预览功能帮助运营人员在发布前确认文章的实际展示效果，避免内容排版问题。但核心 CRUD 功能优先级更高。

**独立测试**: 点击某篇文章的「预览」按钮，验证新窗口打开对应的 `/news/[slug]` 页面，文章内容正确渲染。

**验收场景**:

1. **假设** 运营人员在文章列表页，**当** 点击某篇文章的「预览」按钮，**则** 在新浏览器标签页中打开 `/news/{slug}` 路径的文章详情页
2. **假设** 预览窗口已打开，**当** 查看页面内容，**则** 文章标题、特色图片、正文等内容与管理后台数据一致

### 边界情况

- 未登录用户直接访问 `/admin/content` 怎么办？显示登录表单，不暴露管理页面内容
- 连续输入错误密码怎么办？MVP 阶段不限制尝试次数，仅显示错误提示
- 初始化时 `newsArticles` 为空数组怎么办？显示空状态提示「暂无文章，点击"新增文章"创建第一篇」
- 上传的图片格式不是 webp/png/jpg 怎么办？文件选择器通过 accept 属性限制格式，前端校验不合法格式并提示
- 删除文章后分页状态如何处理？若当前页已无文章，自动返回上一页
- 浏览器刷新后编辑中的数据丢失怎么办？MVP 阶段不持久化，刷新后恢复为初始配置数据

## 需求 _(必填)_

### 功能需求

- **FR-001**: 系统必须在 `/admin/content` 路由下提供内容管理页面，仅桌面端布局（最小宽度 1024px）
- **FR-002**: 访问 `/admin/content` 时必须首先进行登录校验，显示账号密码登录表单。固定凭据：账号 `admin`，密码 `aura1509`。校验通过后方可进入管理页面
- **FR-003**: 登录状态必须保存在 sessionStorage 中，页面刷新后保持登录，关闭标签页后需重新登录
- **FR-004**: 页面必须以表格形式展示所有文章，列包含：序号、标题、标签（分类）、图片路径、操作
- **FR-005**: 表格操作列必须提供「编辑」「预览」「删除」三个操作按钮
- **FR-006**: 页面顶部必须提供搜索框，支持按文章标题实时搜索过滤
- **FR-007**: 页面顶部必须提供标签下拉筛选器，支持按 NewsCategory 筛选文章列表
- **FR-008**: 文章列表必须支持分页，每页展示 10 条记录
- **FR-009**: 点击「新增文章」按钮必须弹出模态框表单，仅包含以下 4 个字段：
  - 图片 (image) — 必填，文件路径输入（支持 webp/png/jpg 格式），仅保存图片路径
  - 标签 (category) — 必填，下拉选择（固定三选一：Breaking news / Event / About Aura）
  - 标题 (title) — 必填，文本输入
  - 内容 (content) — 必填，多行文本输入
- **FR-010**: 新增文章时，系统必须自动生成以下衍生字段：id（唯一标识）、slug（从标题生成）、imageAlt（从标题生成）、publishDate（当前日期）、summary（从内容截取前 150 字符）、cardSize（默认 "small"）
- **FR-011**: 模态框表单必须支持表单验证，4 个必填字段为空时显示错误提示
- **FR-012**: 图片字段必须限制文件格式为 webp、png、jpg，不符合格式时显示错误提示
- **FR-013**: 点击文章行的「编辑」按钮必须弹出与新增相同的模态框表单，预填充该文章的图片、标签、标题、内容四个字段
- **FR-014**: 点击文章行的「删除」按钮必须弹出确认对话框，确认后从列表中移除该文章
- **FR-015**: 点击文章行的「预览」按钮必须使用 `window.open` 在新标签页中打开 `/news/{slug}` 路径
- **FR-016**: 文章数据初始值从 `src/config/news.ts` 的 `newsArticles` 加载，CRUD 操作在客户端内存中管理（state）
- **FR-017**: 页面顶部必须显示当前文章总数统计
- **FR-018**: 删除文章时如果当前页为空，自动跳转到上一页
- **FR-019**: 新增/编辑成功后必须显示操作成功的提示
- **FR-020**: 该页面不需要 SEO 优化（管理页面，非公开页面），不需要 SSR/SSG
- **FR-021**: 该页面不需要响应式设计，仅支持桌面端（≥1024px）

### 关键实体

- **NewsArticle（新闻文章）**: 复用现有 `src/types/news.ts` 中的 `NewsArticle` 接口 — 包含 id、slug、title、category、featuredImage、imageAlt、publishDate、summary、content、cardSize 字段
- **NewsCategory（新闻分类）**: 复用现有分类类型 — "breaking-news" | "event" | "about-aura"
- **ArticleFormData（文章表单数据）**: 新增/编辑表单的精简数据结构，仅包含 4 个字段：image（图片路径）、category（标签）、title（标题）、content（内容）。其余 NewsArticle 字段由系统自动生成
- **AdminCredentials（管理员凭据）**: 登录校验数据 — 固定账号 admin、密码 aura1509

## 假设条件

- 本功能为纯前端 MVP 版本，CRUD 操作在客户端 state 中管理，不涉及后端 API 或数据库
- 页面刷新后数据恢复为 `src/config/news.ts` 中的初始数据（不持久化到 localStorage）
- 复用现有 `NewsArticle` 类型和 `newsArticles` 配置数据，不创建新的数据模型
- 该页面不纳入全站 SEO 和 Lighthouse 审计范围（管理后台页面）
- 该页面使用全站的 Header 和 Footer 组件保持导航一致性，但不需要出现在主导航菜单中
- 登录校验为前端固定凭据校验（admin / aura1509），不涉及后端认证 API
- 登录状态保存在 sessionStorage，关闭标签页后失效
- 新增/编辑表单仅包含 4 个字段（图片、标签、标题、内容），其他 NewsArticle 字段由系统自动生成
- 图片字段仅保存文件路径（string），MVP 阶段不涉及实际文件上传到服务器
- 正文输入使用纯文本 textarea，MVP 阶段不引入富文本编辑器
- 模态框组件基于 Radix UI Dialog 实现（项目已有 `@radix-ui/react-dialog` 依赖）
- 该页面仅支持桌面端浏览器，不考虑移动端和平板端适配
